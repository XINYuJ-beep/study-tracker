界面优先：干净、克制、有质感；宁可少一个功能，也不能让界面显得廉价。

1　产品定义
1.1　一句话
一个把 92 周学习计划拆成「可打勾的小条目」，并按遗忘曲线自动安排复习、测试和抽查的本地打卡 App。
1.2　用户与场景
用户是零基础、时间不固定、需要长期坚持的单个学习者。典型场景：
•  晚上有 40 分钟，打开 App，看到今天推荐的 2–6 个条目，做完打勾。
•  周末有 3 小时，连续打勾十几个条目，把落后的一周补上。
•  突然想测试自己，进入「测试」，做 10 道选择题或抽 10 个概念白板复述。
•  打开统计，看到连续天数、本周时长、各模块完成度。
1.3　不做什么
•  不做账号、不做云同步、不做社交、不做排行榜。
•  不做课程播放器，视频通过搜索名引导到 B 站。
•  不做复杂 AI 功能，所有题目与解析本地内置。

3.1　今日页
•  顶部：日期、问候语、当前模块名。
•  进度环：今日已完成条目数 / 今日目标条目数（默认 3，可在设置改）。
•  推荐列表：按「未完成的最早周」排序，取前 6 条；每条显示 周次、看什么、练什么、预计分钟。
•  复习条：若有到期的自检卡，显示「有 N 张卡待复习」，点击进入测试。
•  底部：今日累计用时、连续打卡天数。
空状态：全部完成时显示一句克制的鼓励文案 + 今日用时，不撒花、不弹窗。
3.2　计划页
折叠屏展开时左侧模块列表、右侧周与条目；手机单栏时逐级下钻。
•  模块卡片：编号、标题、周数、完成百分比、主题色细条。
•  周列表：周次、标题、完成 x/7、状态（未开始 / 进行中 / 已完成）。
•  条目详情：看什么、练什么、产出、预计分钟、所属周目标、打卡按钮、备注。

5　核心逻辑
5.1　时间模型：连续队列，不锁周
•  644 个条目按周次顺序排成一条连续队列，周只是标签，不是锁。
•  周目标默认 2400 分钟（40 小时），可在设置改成 20h / 10h。
•  允许提前：队列里任何条目都可以直接打卡，不必等它“到周”。
•  允许顺延：没做完的条目留在队列里，下周继续，不记“失败”。
•  进度双计：一条是条目完成数，一条是本周已投入分钟数。
•  跨天以凌晨 4 点为界：凌晨 2 点打的卡算前一天。
5.2　今日推荐算法
输入：队列中最早未完成的条目、今日已用分钟、每日预算（默认 90 分钟）。输出：最多 6 条，累计预计分钟不超过预算的 1.2 倍。如果用户提前打了后面的条目，队列自动跳过它们。
没有任何“落后惩罚”：首页只显示“本周还剩 N 分钟 / M 条”，不显示“你落后了”。
5.3　复习队列
每张自检卡有 stage（0–6）和 due_date。到期卡进入今日复习；自评后按规则推进 stage 并重算 due_date。阶段对应 D1/D2/D4/D7/D15/D30/毕业。
5.4　测试解锁
•  只出「已学过」的题：item 完成即视为该周已学。
•  周完成 ≥ 60% 解锁该周选择题；模块完成 ≥ 80% 解锁阶段听力测试。
•  错题本题目在答对 2 次后移出。
5.5　白板抽背
从已学概念中随机 10 个，逐个 60 秒倒计时；结束后自评红/黄/绿，红黄进入次日复习队列。
6　视觉规范
整体气质：安静的纸感 + 一点金属色点缀。不要花哨渐变、不要大面积高饱和、不要圆滚滚的卡通图标。

•  8pt 网格：所有间距为 8 的倍数（8/16/24/32）。

13　没有安卓环境：GitHub Actions 云打包
把项目推到 GitHub，push 后自动构建 APK，手机浏览器直接下载产物，不需要在本机装 Android SDK。
仓库根目录新建 .github/workflows/build-apk.yml：
name: build-apkon: [push, workflow_dispatch]jobs:  build:    runs-on: ubuntu-latest    steps:      - uses: actions/checkout@v4      - uses: actions/setup-java@v4        with: { distribution: temurin, java-version: '17' }      - uses: subosito/flutter-action@v2        with: { channel: stable }      - run: flutter pub get      - run: flutter build apk --release      - uses: actions/upload-artifact@v4        with:          name: apk          path: build/app/outputs/flutter-apk/app-release.apk
•  签名放到 GitHub Secrets（KEYSTORE_BASE64 / KEY_PASSWORD 等），构建时解码写入。
•  每次 push 自动出包，Actions 页面下载 artifact。
•  私有仓库免费额度足够个人使用；公开仓库完全免费。
14　提醒与通知
•  Android 13+ 需动态申请 POST_NOTIFICATIONS 权限；拒绝则不弹提醒，不阻塞使用。
•  每日提醒默认 20:00，可关闭或改时间；用 WorkManager 的普通任务，不强依赖精确闹钟。
•  通知文案：“今天还有 N 条没打卡，预计 X 分钟”，点击直达今日页。
•  错过不补发，不堆叠多条通知；每天最多一条。
15　备份与导出
•  每周日自动导出一次 JSON 备份到应用文档目录，保留最近 4 份。
•  设置里提供「导出备份」（分享到文件/微信）与「导出打卡 CSV」（Excel 可打开）。
•  导入时先校验结构与数量，确认后覆盖，覆盖前自动生成一份回滚备份。
•  清空数据需要二次确认，并提示“不可恢复”。

18　其他必须实现的细节
•  撤销打卡：勾选后 5 秒内可撤销，避免误触。
•  连续天数：当天完成 ≥ 1 条即算打卡，断一天清零。
•  周起始：周一 00:00。
•  空状态：不撒花、不弹窗，只显示一句文案和今日用时。
•  应用图标与启动页：墨蓝底 + 金色细线 Logo，不要用默认 Flutter 图标。
•  隐私：不收集任何数据，不申请网络权限（纯本地）；隐私政策写明“不收集、不上传”。
•  版本号：1.0.0+1，之后每次发版递增。
•  错误日志：本地环形缓冲 200 条，设置里可查看与复制。
•  语言：简体中文；时区：跟随系统。
•  横竖屏：都支持，横屏时计划页强制双栏。

19.4　把 APK 拉到手机
•  最省事：在 ~/dist 执行 python3 -m http.server 8080，手机浏览器访问 http://服务器IP:8080/study-tracker.apk。
•  更稳妥：用 Nginx 托管，配一个随机路径，传完立刻关掉。
•  下载完记得关端口，不要把 8080 长期暴露在公网。
四个坑
ARM 服务器装不上 Android build-tools，先执行 uname -m 确认是 x86_64。
2G 内存容易在 Gradle 阶段 OOM：加 2G swap，并在 gradle.properties 写 org.gradle.jvmargs=-Xmx2g。
首次构建要下载约 2GB 依赖，之后增量构建 1–3 分钟。
release.jks 与密码单独备份，丢了以后无法覆盖升级。
