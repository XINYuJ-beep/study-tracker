## §3 六题型配比

每 item 固定 6 题，按 point 顺序一一映射：

| 题位 | 对应 point | 题型 | 判别标准 |
|---|---|---|---|
| 1 | p1 | 定义识别 | 问「是什么 / 由哪几部分组成」 |
| 2 | p2 | 机制理解 | 问「为什么 / 如何工作」 |
| 3 | p3 | 应用判断 | 给场景问「该用哪个 / 会发生什么」 |
| 4 | p4 | 对比辨析 | 问「A 与 B 的区别」 |
| 5 | p5 | 判断型 | 四选项中一正三误，选出正确的一项 |
| 6 | p6 | 反向选择 | 四选项中三项正确一项错误，选出错误项 |

判断题保持 4 选项 schema 不变，不引入 true/false 二值结构。

## §4 item 三形态

`form` 字段决定该 item 的出题侧重（**不改变题量，始终 6 题**）：

| form | 含义 | 侧重点 |
|---|---|---|
| A | 概念型 | 定义、分类、组成 |
| B | 流程型 | 步骤顺序、状态转换 |
| C | 辨析型 | 易混概念、边界条件 |

m01 实际分布：A=57、C=23、B=4。生成器按 form 调整题干措辞模板，但六题型配比不变。

## §5 存量 321 条处理

| 区间 | 条数 | 现状 | 动作 |
|---|---|---|---|
| q001–q276 | 276 | 8 字段旧格式，无 item_id/day | **回填** item_id / day / source_ref |
| q277–q318 | 42 | 10 字段，item_id 已带 | 不动 |
| q319–q321 | 3 | 周卷，`item_id:""` + `day:0` | **不动**（合法表示） |

回填规则：
- `item_id`：按 q001–q276 对应的 item 键填入（如 `w1d1`）
- `day`：`int(item_id[-1])`
- `source_ref`：统一改为 `item:<item_id>`，便于溯源
- 回填脚本：`tools/backfill_item_id.py`，支持 `--dry-run` 与 `--write`
- 回填前先做一次全量备份 `questions.json.bak_prebackfill`

## §6 十项机械校验

生成器 `validate()` 必须逐条通过，任一失败即中断不落盘。

| # | 校验项 | 规则 |
|---|---|---|
| 1 | itemId 合法性 | `item_id` 必须存在于对应 `m0N.json` 的 items 键中，且所属周落在该模块周区间内 |
| 2 | **题干锚点**（新增） | 题干必须命中该 point 的 `topic`/`desc` 中至少 **2 个二字以上词**，防止 AI 编题飘离知识点 |
| 3 | 选项完整性 | 恰好 4 项，去重后仍为 4 项 |
| 4 | 选项长度 | 单选项 ≤ 28 字；最长/最短长度比 ≤ 2.0 |
| 5 | answer 合法性 | `0 ≤ answer ≤ 3`；全局 answer 分布落在 20%~30% 区间 |
| 6 | explain 长度 | 40 ≤ 字符数 ≤ 80 |
| 7 | 题干长度 | ≥ 8 字 |
| 8 | 题干唯一 | 本批内去重 + 与存量 321 条交叉去重 |
| 9 | 配额 | 每 item 恰好 6 题；每周恰好 3 道周卷（`item_id==""` 且 `day==0`）；总数与预期一致 |
| 10 | day 一致性 | item 题满足 `day == int(item_id[-1])`；周卷满足 `day==0 && item_id==""` |

第 2 条为 v2 新增，v1 与 `gen_w1_mcq.py` 均无。这是防止「AI 写得出题但答非所问」的核心闸门。

## §7 质量兜底四层

| 层 | 手段 | 失败后果 |
|---|---|---|
| L1 | 十项机械校验 | 直接中断，不落盘 |
| L2 | 题干锚点人工抽检（每批抽 10%） | 抽样不合格 → 整批重做该周 |
| L3 | answer 分布监控（每批记录四项占比） | 偏离 20%~30% → 生成器注入均衡约束 |
| L4 | 全库去重（题干 + 选项组合指纹） | 命中重复 → 该题作废重生成 |

## §9 生成器接口契约

### gen_batch.py

```
python3 tools/gen_batch.py --week 2 --write
python3 tools/gen_batch.py --from 3 --to 12 --write --resume
python3 tools/gen_batch.py --week 2 --audit
```

| 参数 | 含义 |
|---|---|
| `--week N` | 单周处理 |
| `--from A --to B` | 区间处理（单批 ≤ 10 周） |
| `--write` | 落盘到 questions.json |
| `--resume` | 读 `gen_state.json` 续跑 |
| `--audit` | 只校验不写 |

**输入**：
- `tools/points/m0N.json`（知识点源）
- `tools/bank/wN.jsonl`（题料，缺失则报缺料并退出码 2）
- `assets/data/questions.json`（存量，用于交叉去重与 id 游标）

**输出**：
- `assets/data/questions.json`（追加）
- `tools/stage/gen_report_wN.log`（校验报告）
- `tools/stage/gen_state.json`：`{"next_id":364,"done_weeks":[2,3,4]}`

**id 分配**：全局游标从 `q322` 起连续分配，不跳号，不复用。

**提交粒度**：一周一 commit，message 格式 `feat(qbank): W{N} 45题入库 q{start}-q{end}`。

## §10 断点续跑

`gen_state.json` 是唯一权威状态：

```json
{"next_id": 364, "done_weeks": [2, 3, 4]}
```

续跑逻辑：
1. 读 `gen_state.json`，若不存在则初始化 `next_id=322, done_weeks=[]`
2. 跳过 `done_weeks` 中的周
3. 每完成一周，原子更新两份文件（先写 `.tmp` 再 `mv`）
4. 中断后重跑，从 `next_id` 继续，已写题目不重复追加

自愈检查：启动时校验 `questions.json` 实际末条 id == `next_id - 1`，不一致则报错退出，要求人工确认。
