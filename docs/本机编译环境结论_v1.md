# 本机编译环境结论_v1（Dart/Flutter on qemu+proot）

状态：**已判定不可行，结案。**
日期：2026-10-27　环境：Android 手机内 Ubuntu 24.04.5 LTS proot（aarch64，内核 5.4.274-qgki）

## 1. 结论

本机（aarch64 proot 容器）无法自建 Flutter 编译环境。`flutter build apk` 走 `dart` -> `frontend_server` -> `gen_snapshot` -> `aapt2` 多进程链路，要求完整 Dart VM 与透明多进程执行，在 qemu-user + proot 组合下两条均不成立。

## 2. 实测证据链（逐层剥离，自下而上）

| 环节 | 结果 | 证据 |
|---|---|---|
| qemu 执行 x64 静态二进制 | 通过 | busybox-static 解包后输出 `QEMU_WORKS_OK`，exit 0 |
| qemu 执行 x64 动态二进制 | 通过 | 补 glibc 后 `dart --version` 输出 `Dart SDK version: 3.13.7 (stable) ... on linux_x64`，exit 0 |
| Dart VM 执行脚本（纯 print） | 失败 | `Illegal instruction`，exit 132 |
| Dart VM fork/spawn 子进程 | 失败 | `dart pub --version` -> `QEMU internal SIGSEGV {code=MAPERR, addr=0x20}` |
| 换 CPU 模型 qemu64 / max | 无效 | 均静默无输出崩溃（此前 exit 0 是管道 tail 的退出码，误读） |
| 扩大 guest 地址空间 -R 4G | 无效 | `Unable to find a guest_base to satisfy all guest address mapping requirements (0x0-0xffffffff)` |
| binfmt_misc 透明执行 | 不可用 | `mount -t binfmt_misc` 返回 0，但 `/proc/sys/fs/binfmt_misc/` 恒空（proot 吞 mount） |

## 3. 根因

1. **地址空间冲突**：Dart VM 需保留大块连续虚拟地址作为堆，proot+qemu 找不到合适 guest_base。
2. **指令集缺口**：JIT 路径触发 qemu-user 未实现的 x86_64 指令（Illegal instruction）。
3. **多进程不可透明**：无 binfmt_misc 则每个子进程都要显式加 qemu 前缀，工具链无法自然工作。
4. `--version` 能过是特例：轻量路径，不启 JIT、不建堆、不 fork，不代表可用。

## 4. 可复用资产（下次别重复踩）

- 多架构运行时已补齐：
  - `dpkg --add-architecture amd64`
  - `/etc/apt/sources.list.d/amd64-archive.list` 内容必须是 `deb [arch=amd64] https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ noble main universe` 及 `noble-updates`；**不能带 -ports**（ports 源 binary-amd64 全 404）
  - `apt-get install -y --no-install-recommends libc6:amd64` -> libc6 2.39-0ubuntu8.9 + libgcc-s1:amd64 + gcc-14-base:amd64（14.1 MB）
  - 加载器 `/lib64/ld-linux-x86-64.so.2 -> ../lib/x86_64-linux-gnu/ld-linux-x86-64.so.2`
- Dart SDK 实际路径是 **`/opt/x64/dart-sdk`**（不是 `sdk`），bin 目录 `/opt/x64/dart-sdk/bin`
- qemu 版本：qemu-user-static `1:8.2.2+ds-0ubuntu1.18`，可执行文件 `/usr/bin/qemu-x86_64-static`

## 5. 操作陷阱（本轮再次踩中，写进纪律）

1. **heredoc 在交互终端会卡进 `>` 续行**：`cat > f <<EOF` 未真正执行，且污染后续输出。一律改 `printf` 一次写成，写完 `cat` + 回显 exit 双验。
2. **管道吞退出码**：`cmd | tail -N; echo EXIT:$?` 拿到的是 tail 的退出码。要真实退出码必须 `cmd > /tmp/x 2>&1; echo $?`。
3. apt update 的 404 报错可能是上一条卡住命令的延迟回显，判断前先确认命令边界。
