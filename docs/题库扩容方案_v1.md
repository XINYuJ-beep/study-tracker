# 题库扩容方案 v1

> 目标：把现有 mcq 276 道（每周 3 道）扩到 **4140 道**（每周 45 道），对齐 plan.json 的 92 周 × 7 天骨架。
> 本文档只写**题目大纲**，不写实际题目。实际题目由 P4 分 92 批生成。

- 版本：v1
- 日期：2026-10-27
- 骨架源：`assets/data/plan.json`（644 item = 92 周 × 7 天，已验证）
- 现状源：`assets/data/questions.json`（`{recall:736, mcq:276}`，mcq 每周恰 3 道，92 周全覆盖）

## 二、item 形态分类与出题策略

plan 的 644 个 item 不是同质的，按内容形态分三类，出题策略不同：

### A 类 · 知识点密集型（约 55%）

特征：`watch` 或 `practice` 里有明确术语、语法、规则、数字。

示例：`w3d3 条件、循环、range`、`w8d3 定位、层叠、优先级`、`w13d4 联合类型、类型收窄`

策略：按 item 字面考点出 6 道，覆盖该 item 全部可考事实。

### B 类 · 操作动作型（约 30%）

特征：`practice` 是「做一件事」，本身不含可考知识；可考知识在 `watch` 段。

示例：`w2d3 建笔记库与模板`、`w12d2 搭 3 个页面`、`w24d5 写清启动方式`

策略：**不考操作步骤**，回头考该 item `watch` 段的知识点。若 `watch` 段仍无可考内容（如「综合」「项目」），降级为 C 类处理。

### C 类 · 复习汇总型（约 15%）

特征：`day` 为周日、或 `watch` 含「周复习 / 阶段复习 / 综合 / 项目 / 复盘 / 联调」。

示例：`w1d7 周复习`、`w12d7 阶段复习`、`w23d6 联调与修复`

策略：6 道题**全部从当周前 6 天的考点反抽**，不引入新知识。与前面 item 撞 hash 时换考点重出。

**识别规则（P4 生成时机器判定）**：

```
if day == '周日' or any(k in watch for k in ['周复习','阶段复习','综合','项目','复盘','联调','刷题']):
    → C 类
elif practice 中无术语且 watch 有具体课程段落:
    → B 类
else:
    → A 类
```

## 三、题型配比（每 item 固定 6 道）

| 序号 | 题型 | 数量 | 说明 |
|---|---|---|---|
| 1–4 | 单选（4 选项） | 4 | 主体，考事实与概念 |
| 5 | 判断（正反配对） | 1 | 与同 item 另一道判断题构成一正一反 |
| 6 | 反向选择 | 1 | 「下列说法**错误**的是」，正确项 = 原单选题的错误项 |

**难度梯度**：

- 第 1–3 道：基础识记（是什么、叫什么、怎么写）
- 第 4–5 道：应用辨析（怎么选、为什么、区别在哪）
- 第 6 道：综合反向（跨该 item 多个考点）

## 四、schema v3 迁移清单

### 4.1 mcq 表新增字段

| 字段 | 类型 | 默认值 | 用途 |
|---|---|---|---|
| `questionType` | TEXT | `'single'` | `single` / `boolean` / `reverse` |
| `itemId` | TEXT | `''` | 绑 plan item（如 `w25d1`），校验规则① |
| `stage` | INTEGER | `0` | SM-2 阶段：0=新题 1–6=间隔序列 7=毕业 |
| `dueDate` | INTEGER | `0` | 下次到期时间戳（ms） |
| `easeFactor` | REAL | `2.5` | SM-2 难度因子，初始 2.5 |
| `rightStreak` | INTEGER | `0` | 连对计数 |

### 4.2 迁移要求

- 用**真实 Migration** 替掉现有的 `fallbackToDestructiveMigration`，schemaVersion 2 → 3。
- 迁移 SQL：`ALTER TABLE mcq ADD COLUMN ...` 六条，`itemId` 回填按 `week` 反查 plan 的 D1，历史 276 道暂绑周首日（后续 P4 重标）。
- 保留 `exportSchema=true`，schema 快照入 `app/schemas/`。

### 4.3 现有 recall 卡不动

736 张 recall 是 plan 镜像卡（每周 8 张 = 1 周回顾 + 7 日 item），不算额外题，不进本次扩容。

## 五、SM-2 挂载（复用现有体系，不新造）

- 间隔序列沿用 `reviewIntervals = [1,2,4,7,15,30,60]`
- 毕业档 `7`（= 答对 7 次毕业）
- 初始 `initialEase = 2.5`
- `rightStreakToClear = 2`（连对 2 次通过）
- `wrongCountToFocus = 2`（连错 2 次进错题本）
- 答错：`easeFactor -= 0.2`（下限 1.3），`stage = max(0, stage-1)`，`dueDate` 提前到次日
- 答对：`stage += 1`，`dueDate = now + reviewIntervals[stage-1] 天`

## 六、按天投放规则

**按「天」投放，不按「周」投放。**

| 推送时机 | 推送内容 |
|---|---|
| 周一 | W(n)D1 的 6 道新题 |
| 周二 | W(n)D2 的 6 道新题 |
| ... | ... |
| 周日 | W(n)D7 的 6 道 + 周综合卷 3 道 |

每日总量 = 当日新题 6 道（周日 9 道）+ SM-2 到期复习题。

**硬约束**：不提前放、不跨天串、不做「一次刷一周」。

## 七、10 条机械校验规则（P4 每批必跑）

| # | 规则 | 实现要点 |
|---|---|---|
| ① | 每题必绑 `week` + `day` + `itemId` | 非空且 itemId 存在于 plan |
| ② | 题干关键词能在对应 `item.watch/practice` 找到锚点 | 分词后取 2–3 个实词，至少命中 1 个 |
| ③ | 单选题正确项恰好 1 个 | `answer` 下标合法且唯一 |
| ④ | 判断题每 item 一正一反配对 | 同 itemId 下 `answer=true` 与 `false` 各至少 1 |
| ⑤ | 反向题答案 ∈ 原单选题错误项 | 交叉比对同 item 的单选题 |
| ⑥ | 题干归一化 hash 去重 | 去标点空格小写后 sha1，全局唯一 |
| ⑦ | 术语表一致性扫描 | 同概念不得两种写法（如「闭包」vs「闭合」） |
| ⑧ | 选项长度比 ∈ [0.5, 2.0] | 最长 / 最短，防止答案靠长度暴露 |
| ⑨ | 答案分布四选项各 20%–30% | 每批统计，偏差则洗牌重排 |
| ⑩ | 解释 ≥15 字且与题干相似度 <0.8 | 防「解释=抄题干」 |

## 八、质量兜底四层（防出题内容出错）

1. **来源锚定**：只出 `item.watch/practice` 范围内的内容，少出评价性/比较性题，多出「下列说法正确的是」型平级事实题。
2. **双路交叉验证**：同考点出两道问法不同但逻辑等价的题，校验脚本扫矛盾即报警。
3. **用户一键标记**：P3 加「这题有问题」按钮（本地 flag 存表），用户做题时天然撞错、批量修复。
4. **分期交付**：每周只交付当周 45 道，错题影响面可控；1–4 周（计算机基础/命令行/Git/HTML）答案最统一、风险最低，主观性强的领域排后期。
